# Лабораторная работа 1 — Mushroom

Вариант 16: классификация съедобности грибов и воспроизводимый конвейер
на `scikit-learn`. Источник — [Mushroom, OpenML ID 24](https://www.openml.org/d/24),
версия 1: 8124 строки, 22 категориальных признака и цель `class`.
Класс `e` означает съедобный гриб, `p` — ядовитый.

Ветка содержит код, пояснения и **невыполненный** ноутбук. Скачивание данных,
обучение, тесты и формирование результатов выполняет пользователь.
Метрики и скриншоты нужно добавить после собственного запуска.
Автоматического обучения через GitHub Actions нет.

## 1. Скачать и проверить данные

```bash
python -m src.data.download
python -m src.data.prepare
```

Первая команда скачивает Mushroom через `fetch_openml(data_id=24)` и сохраняет
`data/raw/mushroom.csv`. Нужен доступ к OpenML. Загрузчик проверяет контрольную
сумму фиксированного CSV и не перезаписывает существующий файл. Повторный запуск
с уже имеющимся корректным CSV не обращается к сети.
Если контрольная сумма отличается, выполнение прекращается с ошибкой.

Вторая команда читает локальный файл, выводит пропуски и частоты **всех** кодов
запаха в train, а также записывает `reports/odor_frequencies.csv`.
Она не обучает модель. Обучение тоже не скачивает данные: если CSV отсутствует,
будет показана команда загрузчика.

В Mushroom есть естественные пропуски `stalk-root`; исходные `?` и пустые
ячейки распознаются как NaN. Все исходные признаки категориальные, поэтому
добавлять искусственные пропуски в две числовые колонки здесь не требуется:
условие задания «если в датасете нет пропусков» не выполнено.
Числовой признак создаётся собственным трансформером.

## 2. Зафиксировать данные через DVC

В репозитории уже есть `.dvc/`, повторный `dvc init` не нужен.
Старый указатель `minidataset.csv.dvc` удалён только из этой ветки:
он относится к другому набору данных.

```bash
dvc add data/raw/mushroom.csv
dvc status
git add data/raw/mushroom.csv.dvc data/raw/.gitignore
git commit -m "Track Mushroom source data with DVC"
```

CSV игнорируются Git. Файлы `.dvc` создаются **после реального скачивания**;
готовые указатели без данных в ветку не добавлены. DVC-кэш локальный;
удалённое хранилище не настроено. На другом компьютере можно повторить
скачивание или отдельно настроить DVC remote и выполнить `dvc push`/`dvc pull`.

## 3. Как считается редкость

Для каждого символа `s` в `odor` трансформер запоминает
`frequency(s) = count_train(s) / len(train)`.
Редкими считаются символы с частотой **строго меньше 0.10**.
Ровно 10% уже не редкость. Порог задан в `RARE_THRESHOLD`;
список символов определяется данными, а не прописан вручную.

В Mushroom запах кодируется одной буквой, поэтому количество редких символов
в строке равно 0 или 1. Добавляемая колонка называется `odor_rare_count`.
Исходная колонка `odor` сохраняется. Для неизвестного символа частота равна
нулю и счётчик равен 1; для пропуска счётчик остаётся NaN, который затем
заполняет числовой импутер.

Частоты обучаются в `fit` и не пересчитываются в `transform`. Внутри
кросс-валидации трансформер заново обучается только на обучающей части фолда.
Тестовая выборка не влияет на частоты, импутацию, кодирование и выбор C.

## 4. Обучить и оценить модель

```bash
python -m src.models.train
```

Конвейер: `RareOdorCounter` → `ColumnTransformer` → `LogisticRegression`.
Числовой счётчик проходит медианную импутацию и стандартизацию;
исходные категории — заполнение модой и one-hot-кодирование.

`GridSearchCV` перебирает `C = [0.1, 1.0, 10.0]` на пяти стратифицированных
фолдах (`shuffle=True`, `random_state=42`). Лучший вариант выбирается по
среднему ROC-AUC и переобучается на всём train. После этого вычисляются
метрики отложенного test. Положительный класс для ROC-AUC и F1 — `p`.

Скрипт создаёт:

- `data/processed/train.csv`, `test.csv` — исходные признаки и цель после
  разбиения, до обучения преобразований; `source_row` — индекс, не признак;
- `models/mushroom.joblib` — весь обученный конвейер;
- `reports/metrics.json`, `training_summary.txt` — метрики и текстовый итог;
- `reports/cv_results.csv`, `run_metadata.json` — подбор C, частоты, seed,
  размеры выборок, SHA-256 и версии библиотек;
- `reports/test_predictions.csv`, `feature_names.json` — прогнозы и признаки;
- `reports/odor_frequencies.csv`, `figures/evaluation.png` — частоты и графики.

После сохранения скрипт загружает собственную модель и проверяет совпадение
предсказаний. Seed, версии, контрольная сумма и ограничение BLAS одним потоком
помогают воспроизвести эксперимент; абсолютная побайтная идентичность между
разными платформами не гарантируется. Повторный запуск обновляет результаты.

Затем зафиксируйте разбиения и модель:

```bash
dvc add data/processed/train.csv data/processed/test.csv models/mushroom.joblib
dvc status
git add data/processed/train.csv.dvc data/processed/test.csv.dvc
git add data/processed/.gitignore models/mushroom.joblib.dvc models/.gitignore
git commit -m "Track lab1 splits and trained pipeline with DVC"
```

Пример использования сохранённой модели:

```bash
python -m src.models.predict data/processed/test.csv
```

обучение и ячейки ноутбука **не запускались**. Проверены только синтаксис,
стиль, структура файлов и отсутствие результатов в ноутбуке.
